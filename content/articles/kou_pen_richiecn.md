## 这个五一假期，决定做这件事

个人站或是个人主页其实并不陌生，N年之前，很多都通过博客来搭建自己的个人站点，发表一些自己关注领域的文章。

有一定建站基础的人，基于WordPress来搭建符合自己个性风格的个人站点。很怀念那个打开网页，显示“hello world”的日子。

回到现在，AI之势席卷全球，新的生产力到来必将引起社会大变革，每个人都会深受影响。
Vibe Coding让技术小白面对一行行代码，心里也荡漾起一层层蠢动。

在这个动不动就专家，混两年就资深的乱世里，真不知道是别人在浮夸，还是自己在附和，到最后自己竟然都信了。
正因如此，打造一张属于自己的个人 IP 名片，才显得尤为必要。

**于是乎，我决定，口喷（Vibe Coding）一个个人主页站！**


## 工具准备：Claude Code + Mimo v2.5 Pro

**Claude Code 是什么？**

简单说，它不是聊天框，是**能动手的编程搭档**。装在终端里，你说需求，它直接写代码、改代码、提交代码。全程不用切窗口，不用复制粘贴。

**为什么选 Mimo v2.5 Pro？**

说实话，最初动心不是因为技术参数，是因为小米搞了个**"百万亿 Token 创造者激励计划"**——你消费 Token，他们按比例返还激励。对于我这种每天高频用 AI 的人来说，相当于白嫖了不少算力。

实测下来效果也没让我失望：速度更快，代码质量更稳，理解中文需求也更准。

目前跑下来，套餐用量在 **44%** 左右，性价比肉眼可见;

安装过程很简单，下面是小米官方的教程，我这里就不多赘述了：

https://platform.xiaomimimo.com/docs/zh-CN/integration/claudecode


装好之后，你只需要"说需求"，它帮你写代码。

## Vibe Coding 实战：从想法到页面

这次建站，我选了最轻量的方案：**纯静态 + Tailwind CSS CDN + React 组件化**。不需要 webpack，不需要 babel，不需要任何构建工具。

整个站大概这几个模块：
- 首页--个人基本介绍
- 历程--简述下职业经历
- 技能栈--技能专长，这个还是需要好好自吹一番的
- 项目--主要是一些AI项目，当前为初版，后面我会放一些干货落地的AI实战项目
- 栗子洞察- 主要分享一些AI新闻事件的见解、工具的使用、产品的思考和落地实战的案例

下面以**"栗子洞察"文章模块**为例，给你看看 Vibe Coding 是怎么玩的。

**第一步：让Gemini 帮梳理下栏目框架**

我把个人背景和要做的事情，发给Gemini，让它帮我梳理了下“栗子洞察”栏目的框架，连对应文章的分类，以及分类需要分享的内容方向都给了出来，我感觉非常不错，直接采纳。

**第二步：我说需求**

```
帮我做一个文章列表页面，叫"栗子洞察"，
风格要简洁专业，每篇文章显示标题、摘要、发布时间
点击能跳转到详情页。
文章主要分类有******
```


**第三步：AI 直接生成**

Claude Code 在终端里唰唰唰输出代码，同时自动创建文件、安装依赖。大概 30 秒后，跟我说："写好了，要预览吗？"

**第四步：本地预览**

```bash
claude preview
```

浏览器自动打开 localhost，页面已经能看了。不满意？直接说"标题字体再大一号"、"加个分类筛选"，AI 当场改。

**第四步：确认，推送**

满意之后，一句命令提交：

```bash
claude commit -m "add lizi-insights module"
```

全程我没有打开过 webpack 配置，没有调过 babel，没有纠结过依赖冲突。

**这就是 Vibe Coding 的感觉：描述需求 → AI 生成 → 预览 → 确认 → 推送。**

**备注：后面内容和细节优化大概用了半天的时间，但是整体DEMO级别的框架出来，2小时完全可以。**

## 部署上线：GitHub Pages + 独立域名

代码写好了，怎么上线？

我选了 **GitHub Pages**，原因就三个：免费、自带 CI/CD、零运维。Push 代码自动部署，连服务器都不用管。

**部署流程：**

1. 代码推送到 GitHub 仓库
2. 开启 GitHub Pages（Settings → Pages → 选分支）
3. 等 1 分钟，网站已经能访问了

**独立域名配置：**

1. richiecn.com
说到域名，真是一言难尽，richiecn.com 五一我刚进行了续费，这个域名注册了23年（2003年注册），趴着不动也已经10多年了，今天终于也算换发了青春......
2. 在仓库根目录放 CNAME 文件，里面写域名
3. 域名后台加一条 CNAME 解析，指向 GitHub 的地址
4. HTTPS 自动生效，不用配证书

Google Analytics 也是一句话搞定：

```
帮我加一下 Google Analytics，追踪 ID 是 G-XXXXXXXXXX
```
这个主要是检测站点的访问数据，可以到Google Analytics申请注册。
AI 自动在页面里插入追踪代码，我连埋点语法都不用查。

## 一点真实的感受

说实话，这个过程中 AI 也不是每次都一次做对。

比如布局细节，我说了三次"再紧凑一点"才满意。再比如响应式适配，第一次生成的手机端有点问题，我截图圈出来，AI 当场修。

但整体来说，**80% 的工作都是一次过**。剩下的 20%，全部用对话的方式调整。

Mimo v2.5 Pro 的能力边界我也摸清楚了：它擅长的是**有明确需求的实现**，不擅长的是**你自己还没想清楚的创意**。所以关键不是"会不会写代码"，而是"能不能把需求说清楚"。这个对产品经理，是天然的友好。
